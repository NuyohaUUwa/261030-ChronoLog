# ChronoLog 产品规划与系统设计

更新：2026-11-07。本文维护产品目标与范围；实现进度统一见 [开发实施状态](开发实施状态.md)，数据与配置见 [技术契约](全栈开发实战手册.md)。规划不等于交付。

## 产品目标与完整范围

快速记录工作、生活和待办，保留原稿，由 AI 润色、分类和提取提醒，再通过卡片、日历与检索回顾。Web 和 Android 共用 Go API，保留注册、登录、多账号隔离。

## 双端体验

Web 以回顾为主：左栏月历和标签，中栏快录和卡片，右栏详情、原稿对照或管理员提示词工具。目标包括标签层级树与热力展示；当前仅有标签列表计数，差距由 W01 跟踪。快录支持 Ctrl/Cmd+Enter。

Android 以快录为主：舒适输入区、单手发送按钮、键盘避让，底部切换快录、日历、检索、设置。首包复用基础流程；FAB 和更多原生适配按反馈推进，不因完整设计未全部实现而阻塞首包。

卡片呈现时间、安全 Markdown 正文、可点击标签、提醒状态和原稿抽屉。复制、编辑、深度对照属于完整目标；仅有服务端更新接口不代表客户端已交付。

## 架构与数据原则

Vue 3 Web → Go API → 用户 Markdown 文件及 SQLite 索引。生产静态资源由 Go embed 内嵌；Android 由 Capacitor 封装并依赖后端。AI 和通知经服务端适配器调用，凭据不进入前端。

先保存独立原稿字段，再异步处理 AI。Markdown + YAML FrontMatter 为笔记权威数据，索引可重建；账号和设置另行持久化、备份。时间、并发与安全约束见技术契约和 [AGENTS.md](../AGENTS.md)。

Windows 承担开发、测试与构建；N100 仅运行预构建产物，当前为 systemd 用户服务和 Git 发布分支。Docker 为后续独立迁移方案，已有模板不代表镜像已验证。N100 连接须逐批明确授权。

## 交付顺序与边界（2026-11-07 用户明确）

严格按照三阶段顺序推进交付，遵循“功能 > 性能 > 审查 > 交互”：
1. **阶段一：服务端功能与接口开发（优先推进）**：
   - 真实 AI 大模型接口接入（OpenAI / DeepSeek 等兼容协议，配置 API Key 端到端跑通润色与标签抽取）。
   - 实用推送渠道扩展（Bark / 自定义 Webhook 发送器，支持真机接收弹窗通知）。
   - 待办取消 API（`POST /api/v1/notes/:id/reminders/:rem_id/cancel`）及通知深链直达参数基础支持。
2. **阶段二：Web 端全量体验与数据可视化**：
   - 完整记事编辑：支持正文、Markdown 排版与多层级标签二次修改与原子写回。
   - 待办状态联动：卡片与日历视图一键完成/取消待办，状态即时刷新。
   - 数据可视化：多层级标签树导航折叠与过滤；日历时间线与历史记事热力图展示。
   - 通知深链直达：具备基础可用功能即可，点击通知拉起页面定位并高亮对应笔记，不追求过度设计。
3. **阶段三：安卓移动端开发（原生深度适配）**：
   - 基于阶段二成熟 Web 构建产物，通过 Capacitor 进行 Android 原生深度适配。
   - 定制 Android 原生状态栏与沉浸式手势适配、原生通知栏推送接收器（或协同 Bark）及离线缓存基础支持。
   - 构建交付 Debug/Release APK 并通过 USB 联调跑通完整流程。

资源目标是单进程、无独立数据库或前端服务。早期提出的空闲内存 10–15 MB 尚未实测，需记录数据量、并发及 AI 工作状态后判断。跨笔记工具导入兼容性也需实际验证。

范围或优先级改变时更新本文并同步进度表；日常任务状态不在本文重复维护。
