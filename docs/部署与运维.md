- `release.json` 记录源码提交和构建目标；校验文件校验压缩产物。Git 会保存历史产物，日后体积增长时再迁移到 GitHub Releases；不得为节省空间擅自重写历史。

## 本机构建

PowerShell，项目根目录，在测试通过且源码提交后：

```powershell
Push-Location web
npm ci
npm run build
Pop-Location
New-Item -ItemType Directory -Force server/assets/web_dist | Out-Null
Copy-Item web/dist/* server/assets/web_dist/ -Recurse -Force
Push-Location server
$env:GOOS = 'linux'
$env:GOARCH = 'amd64'
$env:CGO_ENABLED = '0'
go build -trimpath -ldflags='-s -w' -o ../out/chronolog .
Pop-Location
Remove-Item Env:GOOS,Env:GOARCH
```

`out/`、`web_dist/` 均被忽略。发布时压缩二进制，生成 SHA256 和源码提交清单，将这些文件及 `scripts/deploy-n100.sh` 放到独立的 deploy/n100 分支工作目录，提交后推送。main 与发布分支均不得强制推送。

## 服务器更新

此前正式服务记录为 `fun@10.126.126.9`、`/home/fun/projects/chronolog`、`systemd --user chronolog.service`。后续获准更新时沿用现有方式；Docker 迁移为单独任务。正式目录核查必须确认服务实际路径与这些记录相符，否则先调整部署方案，不能覆盖不明文件。

获准后，在正式目录的独立发布检出目录（首次用 Git clone 建立）操作：

```sh
git -C /home/fun/projects/chronolog/releases-git pull --ff-only origin deploy/n100
cd /home/fun/projects/chronolog/releases-git
bash deploy.sh /home/fun/projects/chronolog
```

`deploy.sh` 校验 SHA256，将新二进制解压到临时文件，停止正式服务并备份配置、数据、旧程序与服务定义，再替换、启动、验证本机正式健康接口。失败自动恢复旧程序并重启。备份留在正式目录下 `backups/`，包含敏感数据，只允许服务账号访问。

不重置账号，不清空数据，不自动切换 AI／通知模式。管理员新注册需要 `ADMIN_SETUP_KEY`，已有用户继续使用原密码；如未配置，管理员候选邮箱注册会被拒绝，应在受控环境配置密钥，不能在文档或日志中填写真实值。

部署验收仅检查正式服务状态、版本校验、健康接口及页面资源，不在 N100 注册测试账号、调用开发 AI、执行故障注入。线上健康通过不等于真实模型质量／手机通知送达已验收。
